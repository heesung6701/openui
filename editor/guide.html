OpenUI YAML 스펙 해설

OpenUI는 UI 컴포넌트를 OpenAPI처럼 YAML로 기술하는 스펙이다. YAML 문서가 단일 원천(SSOT)이고, Figma 컴포넌트와 웹·Compose·React 구현은 이 문서에서 파생되거나 이 문서와 대조된다.

한눈에 보기

토큰

토큰 파일은 W3C DTCG 2025.10 형식을 YAML로 그대로 쓴다. 외부 디자인 토큰 도구와 바로 호환하기 위해서다. 토큰 파일에는 여러 컴포넌트가 함께 쓰는 전역 토큰(팔레트, 시스템 색, 타입 스케일, 텍스트)만 둔다. 한 컴포넌트가 쓰는 토큰은 그 컴포넌트 문서 안에 둔다(컴포넌트 토큰).

md:
  sys:
    color:
      $type: color
      primary: { $value: "{md.ref.palette.primary40}" }   # alias: 반드시 따옴표
    shape:
      corner-full: { $type: dimension, $value: { value: 9999, unit: px } }
  • $value가 있으면 토큰, 없으면 그룹이다. $type은 직접 쓰거나, alias 대상이나 부모 그룹에서 물려받는다.
  • 지원 타입은 11종이다: color, dimension, number, duration, cubicBezier, fontFamily, fontWeight, shadow, typography, gradient, 그리고 텍스트용 string.
  • color는 {colorSpace: srgb, components: [r, g, b]} 객체로만 쓴다. hex 문자열 단독은 DTCG 2025.10에서 허용되지 않는다.
  • alias "{a.b.c}"는 그룹이 아닌 토큰을 가리켜야 하고 타입이 맞아야 한다. 순환 참조는 오류다.

모드는 Resolver 문서로 정의한다. set은 모드가 하나(default)인 컬렉션이고, modifier는 context 이름들이 모드가 된다.

resolver컬렉션모드예
set ref, sys, comp같은 이름default팔레트, 모서리, comp 토큰
modifier themethemelight, darksys 색상
modifier localelocaleen, ko텍스트 토큰
modifier window, orientation, device같은 이름compact…, portrait…, phone…조건만 정의. 값은 컴포넌트 토큰의 $when

토큰 하나는 정확히 한 set, 또는 한 modifier의 모든 context에 있어야 한다. 이 규칙 덕분에 Figma variable 컬렉션/모드와 웹의 CSS 변수 + data-theme 속성으로 그대로 옮겨진다.

텍스트 토큰

화면에 나오는 모든 텍스트는 텍스트 토큰이다. 텍스트 토큰은 $type: string인 토큰이고, 토큰 경로가 그 텍스트의 ID다. 다국어 시스템은 이 ID를 번역 키로 쓴다.

# tokens/text.en.tokens.yaml          # tokens/text.ko.tokens.yaml
text:                                 text:
  $type: string                         $type: string
  button:                               button:
    label: { $value: Button }             label: { $value: 버튼 }

언어 하나가 locale modifier의 context 하나다. 컴포넌트는 리터럴 대신 ID를 쓴다.

props:
  label: { type: text, default: "{text.button.label}" }
anatomy:
  root:
    children:
      badge: { kind: text, text: "{text.gallery.badge}" }
  • 리터럴 텍스트는 오류다. text part의 text와 text prop의 default는 텍스트 토큰이어야 한다. 다른 타입의 토큰을 가리켜도 오류다.
  • 번역 누락도 오류다. 한 언어에 ID가 빠지면 token "text.button.label" missing in context "ko" of modifier "locale"가 난다.
  • ID 이름은 text.<컴포넌트>.<이름>을 권장한다. 공통 문구는 text.common.*에 두고 alias로 재사용한다. 브랜드명처럼 언어와 상관없는 텍스트는 set에 둔다.
  • 렌더러는 선택된 locale로 값을 해석해 텍스트로 넣는다. 에디터 상단에서 locale을 바꾸면 프리뷰가 바로 그 언어로 바뀐다.
  • 앱이 런타임에 넘기는 사용자 데이터(이름 등)는 리터럴이어도 된다. 문서용 문자열(name, description)은 화면에 그려지지 않으므로 대상이 아니다.

Figma에서는 STRING 변수(scope TEXT_CONTENT)가 되고, locale 컬렉션의 mode가 언어다. 텍스트 레이어의 characters에 변수를 바인딩한다. 언어 하나를 풀면 {ID: 문자열} 평면 맵이라 JSON, strings.xml, .strings 같은 번역 파일로 그대로 옮길 수 있다.

조건부 토큰

값이 상황에 따라 달라지면 그 차이는 토큰 정의에 둔다. 컴포넌트에는 리터럴 값이 없고 토큰만 있다. 토큰이 "언제 어떤 값인지"를 가진다.

  • 언제: resolver의 modifier가 모드를 정의하고, context별 조건을 적는다($extensions["org.openui"].when). DTCG Resolver가 허용하는 확장 위치라 다른 도구와도 호환된다.
  • 어떤 값: 컴포넌트 토큰이 자기 정의 안의 $when에 모드별 값을 둔다. 전역 토큰이라면 context마다 토큰 파일에 둔다.
# tokens/*.resolver.yaml — 모드와 조건
modifiers:
  window:
    contexts: { compact: [], medium: [], expanded: [] }
    default: compact
    $extensions:
      org.openui:
        when:
          compact:  { width: { max: 600 } }               # 너비 < 600
          medium:   { width: { min: 600, max: 840 } }     # 600 ≤ 너비 < 840
          expanded: { width: { min: 840 } }

# components/card.yaml — 카드 토큰이 창 크기별 값을 가진다
data:
  tokens:
    padding:
      $type: dimension
      $value: { value: 16, unit: px }
      $when:
        window=medium: { value: 24, unit: px }
        window=expanded: { value: 24, unit: px }
조건값웹에서
width, height{min?, max?} px(dp). min ≤ 값 < max@media (600px <= width < 840px)
orientationportrait, landscape@media (orientation: landscape)
devicephone, tablet, desktop, tv, watch앱이 data-device 지정
colorSchemelight, darkprefers-color-scheme
languageBCP 47 태그:lang(ko)
  • 한 modifier는 한 종류의 조건만 쓴다. 조건끼리 겹치면 오류이고, 어디에도 맞지 않으면 기본 context를 쓴다.
  • 모드를 고르는 순서는 명시적 선택 → 조건 → 기본값이다. 에디터 상단의 모드 선택은 명시적 선택이라, 조건을 무시하고 원하는 context를 미리 볼 수 있다.
  • 인스턴스가 고르는 값(버튼 강조 스타일 등)은 modifier가 아니라 컴포넌트의 mode prop이다: style: { type: mode, values: [filled, outlined, text], default: filled }. 토큰은 $when: { style=outlined: … }로 그 값마다 다른 값을 가진다.
  • $when 키가 여러 개 맞으면 모드가 적은 키부터, 같으면 문서 순서로 덮어쓴다. 예: style=text,device=desktop은 device=desktop보다 우선한다.
  • Figma는 모드를 자동으로 고르지 않는다. 조건별 화면은 프레임에 explicit mode를 지정해 만든다. 컴포넌트 토큰은 컴포넌트별 variable collection(모드 = mode prop 값)이 되고, 인스턴스는 explicitVariableModes로 모드를 고른다.

컴포넌트 문서

컴포넌트 하나는 kind: Component YAML 파일 하나다. 여섯 부분으로 나뉘며, part(해부도 요소)와 slot(사용자가 콘텐츠를 넣는 자리)을 구분한다.

Material 3 Button을 줄이면 이렇다. 다섯 스타일(filled, outlined, text, elevated, tonal)은 UI 트리가 같으므로 variant가 아니라 mode prop이고, 아이콘 part를 보이는 withIcon만 variant다.

kind: Component
metadata: { id: button, name: Button }
data:
  props:
    label: { type: text, default: "{text.button.label}" }
    style: { type: mode, values: [filled, outlined, text, elevated, tonal], default: filled }   # 값만 다름
    icon:  { type: instance, default: icon-add }
  variants:
    withIcon: { values: { "false": {}, "true": {} }, default: "false" }                        # 구조가 바뀜
  states: [enabled, hovered, focused, pressed, disabled]
  tokens:                                   # 이 컴포넌트가 쓰는 토큰 = "{button.<이름>}"
    container-color:
      $type: color
      $value: "{md.sys.color.primary}"
      $when:
        style=outlined: "{md.sys.color.transparent}"
        style=text: "{md.sys.color.transparent}"
        style=elevated: "{md.sys.color.surface-container-low}"
        style=tonal: "{md.sys.color.secondary-container}"
    leading-space:
      $type: dimension
      $value: { value: 24, unit: px }
      $when: { style=text: { value: 12, unit: px } }
    block-space: { $type: dimension, $value: "{md.sys.space.zero}" }
    container-height: { $type: dimension, $value: { value: 40, unit: px } }
  anatomy:
    root:
      kind: frame
      layout: { direction: row, padding: ["{button.block-space}", "{button.trailing-space}", "{button.block-space}", "{button.leading-space}"],
                width: hug, height: "{button.container-height}" }
      children:
        icon:  { kind: instance, prop: icon }
        label: { kind: text, text: { prop: label } }
  styles:
    base:
      enabled: { root: { fill: "{button.container-color}" } }
    withIcon=false:
      enabled: { icon: { visible: false } }

컴포넌트 토큰: 스타일 값은 리터럴도, 전역 토큰도 아닌 이 컴포넌트의 토큰만 가리킨다. 그래서 "이 버튼이 언제 어떤 값을 쓰는지"가 버튼 문서의 tokens 한 곳에 모인다. 컴포넌트 토큰은 전역 토큰(md.sys.*)을 alias하거나 리터럴 값을 가진다.

무엇이 다른가표현예
part가 생기거나 없어짐, 배치 방향variantwithIcon, 체크박스 type
값만 다름, 인스턴스가 고름mode prop + 토큰 $when버튼 style, 체크박스 error
값만 다름, 환경에 따라조건 + 토큰 $when창 너비별 패딩, 단말별 높이
런타임 상호작용statehovered, pressed
  • variant는 UI 트리가 바뀔 때만 쓴다. 축의 값들 사이에 구조 값(visible, direction, position, hug/fill 등) 차이가 없으면 검증 오류다.
  • 모든 값은 그 컴포넌트의 토큰이다. 치수·색·불투명도에 8px, [0, 24px], #6750A4 같은 리터럴을 쓰거나 {md.sys.color.primary} 같은 전역 토큰을 직접 가리키면 오류다. 리터럴로 남는 것은 키워드·열거값·boolean 같은 구조 값뿐이다.
  • part 종류는 여섯 가지다: frame, text, instance, slot, vector(svg path), image(src). 최상위는 항상 root frame이다.
  • state는 이름 하나만 쓴다. data와 part에는 x- 확장 키를 둘 수 있고, Figma 고유 정보는 x-figma에 둔다.

속성 어휘

스타일 속성은 29개로 고정된다. Figma auto layout과 paint 개념을 플랫폼 중립적인 이름으로 옮긴 것이고, part 종류에 맞지 않는 속성은 검증 오류다. layout 열이 ✓인 속성만 anatomy의 layout에 쓸 수 있다. 표의 치수·색·0..1은 모두 그 타입의 토큰이다.

hug는 내용 크기에 맞추고 fill은 부모의 남는 공간을 채운다. position: absolute + fill은 부모를 덮는 오버레이다. Material 3의 state layer가 이 방식을 쓴다.

스타일 해석 규칙

state 계층이 variant 구체성보다 우선한다. 그래서 "pressed면 이 색" 같은 공통 규칙을 base에 한 번만 쓰면 모든 variant에 적용된다. variant 조합 V와 state s에 대해 part별 속성을 다음 순서로 덮어쓴다.

  1. anatomy의 layout 값에서 시작한다.
  2. V에 맞는 styles 항목만 고른다. base는 항상 포함하고, 축 개수가 적은 것부터(같으면 문서 순서) 정렬한다.
  3. 정렬된 항목마다 기본 state(states의 첫 항목) 블록을 덮어쓴다.
  4. s가 기본 state가 아니면, 다시 처음부터 s 블록을 덮어쓴다.

V에 없는 축은 그 축의 default를 쓴다. 예를 들어 다음 스타일이 있을 때:

styles:
  base:
    enabled: { root: { fill: "{c.one}" } }
    pressed: { root: { fill: "{c.two}" } }
  layout=stacked:
    enabled: { root: { direction: column, fill: "{c.three}" } }
  layout=stacked,badge=true:
    enabled: { root: { fill: "{c.four}" } }
variantstateroot.fill이유
layout=stackedenabled{c.three}같은 state 안에서는 더 구체적인 variant가 이긴다
layout=stackedpressed{c.two}pressed 계층이 enabled 계층 뒤에 적용된다
layout=stacked, badge=trueenabled{c.four}축 2개 식이 축 1개 식을 이긴다(문서 위치 무관)

체크리스트

체크리스트(kind: Checklist)는 컴포넌트가 의도대로 구현됐는지 확인하는 항목 목록이다. 컴포넌트당 파일 하나를 두고, 항목은 자동과 수동 두 종류다.

kind: Checklist
metadata: { id: button, component: button }
items:
  - id: filled-container
    title: "Filled 컨테이너 = primary"
    check: { variant: { style: filled }, state: [enabled, hovered], part: root,
             property: background-color, expect: "{md.sys.color.primary}" }
  - id: ripple
    title: "pressed 리플"
    manual: true
  • 자동 항목: variant × state × 모드 조합마다 컴포넌트를 렌더하고 part의 computed CSS 값을 읽는다. 생략한 축·state는 모든 값을, 생략한 모드는 컴포넌트가 실제로 쓰는 modifier만 모든 context를 검사한다. mode prop 값도 mode: { style: outlined }로 지정한다.
  • 텍스트 항목: property: text는 part에 렌더된 텍스트를 읽어, 그 케이스의 locale로 해석한 텍스트 토큰과 비교한다. 예: expect: "{text.button.label}"은 en에서 Button, ko에서 버튼이어야 통과한다.
  • 판정: 기대값을 프로브 요소에 설정해 브라우저가 양쪽을 같은 방식으로 정규화하게 한 뒤 비교한다. px는 0.05px 오차를 허용하고, 측정값이 비어 있으면 실패다.
  • 수동 항목: 포커스 링, 리플, 터치 타깃처럼 v0.1 어휘로 표현하지 못하는 것을 사람이 보고 체크한다.
  • 기대값 원칙: 컴포넌트가 쓰는 comp 토큰이 아니라 sys 토큰이나 공식 스펙의 리터럴을 쓴다. 그래야 YAML 작성, comp→sys 연결, 렌더러가 한꺼번에 교차 검증된다.

v0.1의 한계와 다음 단계

v0.1은 정적인 외형과 구조를 다룬다. 상호작용과 모션은 아직 수동 체크로 확인한다.

  • 표현하지 못하는 것: 리플, 포커스 링 오프셋, 애니메이션, state 조합(enabled,selected), boolean 토큰, 텍스트의 자리표시자({count}개)와 복수형, 번역 fallback(ko-KR→ko), RTL 레이아웃.
  • 조건의 한계: 한 context에 조건 하나만 둔다(너비이면서 가로 방향 같은 AND 없음). pointer, contrast, reduced motion 조건도 아직 없다.
  • 작성이 번거로운 것: variant 식에 OR가 없어 같은 블록을 반복해야 한다. 존재하지 않는 variant 조합을 제외할 방법도 없다.
  • 아직 정의하지 않은 것: 렌더러용 정규화 JSON(exchange 포맷)은 v0.2에서 정의한다. 지금 렌더러는 YAML을 직접 읽는다.
  • 다음 단계 후보: Compose·React 렌더러, 비주얼(인스펙터) 편집, YAML→Figma 생성 플러그인.
